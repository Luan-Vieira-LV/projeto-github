Principais conceitos

Entenda o que move o GitHub

A plataforma é organizada em blocos que ajudam profissionais a manter código, revisão e histórico em ordem, mesmo em times grandes.

R

Repositório

É o espaço central do projeto, onde ficam todos os arquivos, histórico de alterações e documentação. Pense nele como a pasta principal do seu trabalho.

B

Branches

As branches permitem criar linhas paralelas de desenvolvimento. Assim, você pode testar novas ideias sem afetar diretamente o código principal.

C

Commits

Cada commit registra uma alteração com uma mensagem descritiva. Isso cria um histórico claro do que foi feito e quando foi feito.

P

Pull Request

É a etapa de revisão e aprovação de mudanças antes de integrar no projeto principal. Ajuda a manter a qualidade e a segurança do código.

I

Issues

São tarefas, falhas, melhorias ou pendências do projeto. Elas servem como backlog organizando o trabalho e mantendo a equipe alinhada.

M

Merge

O merge integra as alterações aprovadas na branch principal. É o momento em que o trabalho individual se transforma em progresso do projeto.

Fluxo de trabalho

Como uma equipe usa o GitHub no dia a dia

1

Criar

Um time inicia um repositório e organiza arquivos, documentação e regras de uso.

2

Desenvolver

Cada pessoa trabalha em branches separadas para implementar tarefas específicas.

3

Revisar

Pull requests permitem comentar, testar e validar alterações antes do merge final.

4

Lançar

Quando tudo está validado, as mudanças entram na branch principal e o projeto avança.
